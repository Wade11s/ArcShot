# Scroll Capture 原生原型：实机验证记录

关联：[实机验证 Scroll Capture 的双向拼接、浮层捕获与输入协作](https://github.com/Wade11s/ArcShot/issues/15)。

## 结论

在用户 MacBook Air 的单一内建显示器上，**单进程、按精确预览 window ID 排除的
ScreenCaptureKit 单帧请求路径，已在受控、静态、唯一可验证的原生 GPUI 夹具上完成端到端验证**。
受控慢速双向滚动、反向去重、外侧/内侧预览排除、Enter/双击完成、Esc 取消、
快捷键重启、输入拦截、PNG 输出和若干失败恢复均取得了真人操作与运行日志证据。

这不是任意应用、任意滚动速度或任意长图的兼容性承诺。快速/不连续位移会显式失败；
最终原生适配路线由后续票据决定，资源预算和验收门槛另行确定。

## 环境与路径

- Mac14,2，arm64，macOS 27.0.1 (26A434)。
- 内建显示器逻辑尺寸 1470×956，捕获 scale=2。
- Rust/Cargo 1.99.1；GPUI 0.2.2；screencapturekit 11.1.1。
- 用户自行授予 Screen Recording、Input Monitoring、Accessibility，随后 preflight 三项均为 true。
- 同一 GPUI 进程持有目标夹具与控制器/预览。SCK display filter 使用
  `excludingWindows` 排除控制器的精确 window ID；不按 bundle/application 排除目标。
- `SCScreenshotManager.capture_image` 单帧请求串行执行，BGRA、显式 sRGB、sourceRect 逻辑点、
  输出物理像素，关闭光标。严格唯一整数垂直位移 + 整个已知重叠逐像素验证，才扩展连续文档。
- 原始触控板/滚轮事件在选区内原样放行，其他点击被 tap 吞掉；预览 NSWindow 鼠标穿透。
  本轮没有外接滚轮、嵌套滚动、真实第三方应用或任意动态网页兼容承诺。

## 分项真人证据

| 项目 | 结果与本机证据 |
|---|---|
| 外侧预览、双向拼接、反向去重 | 一个会话 99 帧、42 次有效位移（19 正、23 反）；连续范围覆盖 679 逻辑点，结果 1360×2438 物理像素。反向不重复扩展，全部接纳帧通过夹具真值。Esc 约 12.218 秒后取消，无输出。 |
| 选区内预览、指针穿透与滚动更新 | 用户确认指针直接在预览上时可滚动且预览更新；日志有正反向位移及真值通过。另一会话 31 次有效位移、最大 1360×2962，Esc 取消，无输出。 |
| 左侧预览与双击完成 | 左侧预览下 10 次有效位移，完成图 1360×3088；双击触发 Finish，编码 PNG 958,211 字节，剪贴板类型 PNGf 与字节数一致。未保存图像文件。 |
| Enter、单击拦截与 PNG 输出 | 一个完成会话为 1360×1832、568,689 字节；Enter 触发编码，剪贴板类型 PNGf 与字节数一致。该轮单击未产生目标点击回执，Enter 未泄漏到夹具。另有 1360×1718、532,782 字节的完成记录。 |
| 单帧直接完成 | 无滚动完成也得到 1360×1080、334,500 字节 PNG，说明初始已验证单帧可显式完成。 |
| 无法可靠重叠 | 一个会话出现 `no unique exact overlap (0 candidates)`，此前连续结果 1360×1832；停止并保留已验证部分，不自动复制。日志不能单独区分采样缺口、滚动过快或内容变化，不能将这类情况记为兼容通过。 |
| 内容变化 | 有已验证结果后按 M，目标收到 M，显式停止并保留部分结果；首帧确认前按 M 则明确无图、无输出。U 恢复、Discard 均正常。未自动复制不完整结果。 |
| 重启 | Cmd-Shift-A 丢弃当前结果并开始新会话；随后 Esc 可取消。日志 `command=3`，无旧结果自动输出。 |
| 目标关闭/焦点丢失 | Q 只关闭夹具，控制器保留；目标焦点/可用性检查显式停止。切换其他应用也先触发目标失去焦点并停止，不继续采样或自动复制。 |
| 程序化预览/取消对照 | 外侧与覆盖预览各自 14 个连续正确帧后内部取消，无 PNG。仅作自动对照，不替代以上真人操作。 |

“剪贴板通过”这里指应用返回接受、系统剪贴板报告 PNGf 类型和相同字节数；
本轮没有把逐像素解码/粘贴后的视觉检查单独列为已验证事实。所有图像默认仅存在于内存；
只在用户显式完成时写剪贴板，没有自动落盘。

## 测量，不是 V1 预算

- 常规单帧请求多约 18–36 ms，另有实验性 50 ms 间隔；实际吞吐不是 30/60 fps 承诺。
- 接纳位移时拼接约 33–37 ms；自然滚动和反向操作已覆盖。
- 编码随图像高度与机器状态变化：1360×1080 约 805 ms，1360×1832 约 1305 ms，
  1360×3088 约 2260 ms。
- 进程峰值 RSS 示例：约 131 MiB（短时自动对照）、约 253 MiB（完成会话）、
  约 305 MiB（内侧预览长会话/失败测试）。不同进程与场景不可直接作线性外推。
- 96 MiB 原始拼接图实验上限、180 秒实验时限、完整 native/Metal/编码峰值、资源不足恢复，
  以及自然应用性能尚未由这些短会话定案。

## 失败与未验证边界

- 运行中直接撤销 Screen Recording 未单独测试。常规撤销需要切换系统设置，目标焦点检查先停止；
  用户决定不把该极端路径作为本次门槛。初次未授权 preflight 已拒绝启动；不能声称已验证运行中撤权。
- 未测试外接滚轮、快速甩动的可靠拼接、惯性全序列、横向/对角滚动、嵌套滚动、
  低纹理/重复自然内容、固定表头、动态加载、第三方 App、系统保留快捷键或安全输入。
- 曾经观察到 cocoa `NSScreen.deviceDescription` 空引用崩溃及窗口几何过渡失败；
  后续路径有修正和成功记录，但未建立专门的系统级回归证明。
- 受控 oracle 只诊断自有夹具，不是任意应用的来源/内容身份证明。窗口排除通过也不代表
  对其他遮挡、系统弹层、受保护内容或跨窗口选区作承诺。
- 精确整数位移算法不承诺亚像素/重采样自然内容。无法验证重叠、内容改变、焦点/目标/拓扑变化
  时继续采用显式停止，不静默补洞。

## 后续

本票据只解决原生受控路径的可行性问题，保留 throwaway 原型在 `prototype/manual-scroll`，
不合并 main。后续原生路线选择、真实受控场景、资源预算和验收门槛继续由地图的后续票据决定。
`cargo fmt`、`cargo clippy --all-targets --all-features -- -D warnings`、7 个单元测试已运行；
它们不构成 macOS 实机验收的替代品。
